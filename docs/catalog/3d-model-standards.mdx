# <Icon name="rotate-3d" size="1em" /> 3D Model Standards

<PageIntro illustration="catalog" meta={['For 3D modellers', 'Any 3D application']}>

The rules every model must meet before it enters the **BMR catalog**. Use any tool — only the exported file has to conform.

</PageIntro>

A catalog item is **data** (see [Anatomy of a Catalog Item](item-anatomy)) plus the **3D model**. This page covers the model. Read the summary, tick the checklist, then send.

---

## <Icon name="circle-check" size="1em" /> Requirements at a glance

| Area | Requirement |
|---|---|
| **Format** | Single **.glb** with embedded textures (preferred). **.usdz** accepted if fully self-contained. |
| **Geometry** | ≤ 50,000 triangles. Origin at the object centre. Model faces **−Y**. Scale & rotation **applied**; location **not** applied. Static geometry only. |
| **UVs** | One UV channel per mesh, valid and non-overlapping. Screen surfaces fill the full **0–1** UV space. |
| **Materials** | **PBR metallic-roughness** only. Each material uniquely named — `ProductName_PartName` (e.g. `EasyRoomDesk_Frame`). Any screen material's name must start with `Screen` (e.g. `Screen_ProductName`). |
| **Textures** | PNG or JPEG, embedded, sized **512 / 1024 / 2048 px** square. **Never above 2048.** Normal maps use the **OpenGL (+Y)** convention, not DirectX. |
| **Scene** | Mesh + materials only. No lights, cameras, hidden objects, rigs, animation, drivers, or custom properties. |

## <Icon name="mail" size="1em" /> Submitting your model

1. Export **one self-contained file** — `.glb` preferred, `.usdz` accepted — with all textures embedded.
2. Add a short description: **name**, **brand**, **SKU**, and **where it goes** — floor, wall, ceiling, table, rack, on top of a display, or on a mount (VESA or camera screw).
3. Making a **mount** or bracket? Say where equipment attaches and what fits there (VESA, rack, ¼"-20 camera screw). BMR places the [mounting points](ports-and-devices#-mounting-points).
4. Send it to **support@bettermeetingrooms.com**. BMR checks it against these standards and gets back to you if anything needs changing.

The model is half of a catalog entry. For the whole item — model **and** data — see [Requesting a Catalog Item](requesting-items).
